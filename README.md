# Carp-taxi ブラウザ版

iPhone 版タクシーアプリを、ブラウザで動く形に作り直したものです。ビルド不要の静的サイトなので、このフォルダをそのまま公開すれば動きます。

## 公開のしかた

位置情報とカメラは https のサイトでしか使えません。次のどれかで公開してください。

- Netlify：app.netlify.com/drop にこのフォルダをドラッグ
- GitHub Pages：リポジトリに入れて Pages を有効化
- Firebase Hosting：`firebase deploy --only hosting`（公開フォルダにこの中身を指定）

## 初回の設定（端末ごとに 1 回）

開くと「初期設定」が出るので、Google Maps の API キーを入力します。キーは Google Cloud コンソールで作成し、次の API を有効にしてください。

- Maps JavaScript API
- Routes API
- Geocoding API
- Places API (New)

キーには「ウェブサイトの制限」で公開先の URL を登録してください（他のサイトから使われないようにするため）。

## 入っている機能

- 地図、現在地、追跡、拡大縮小、渋滞情報
- メーターと同じ並びの「空車・実車・支払」ボタン（「実車」で乗車、「支払」で降車の位置を高精度で記録し、その間の走行ルートと曲がり角の通過時刻を保存）
- 目的地検索（ピンはドラッグで修正可）、2 点間ルート
- ナビ（複数ルートの比較、有料道路・高速の回避、音声案内、進行方向を上にした表示、ルートを外れたときの自動再検索、到着予定時刻）
- 配車記録（GO が鳴った時刻、上客・危険客、理由、年代、降車場所、メモ）
- 統計オーバーレイ（曜日の選択、時刻スライダー、時刻差の色分け）
- 探索ナビ（配車記録から需要の高いエリアを選んで巡回ルートを作成）
- 高速 IC ハイライト（11 区間。位置は設定から調整可）
- S ボタン（長押しでインカメラ録画とルート追跡。録画一覧、110 番への発信リンク）
- GO 配車統計、CSV の書き出しと取り込み

## サーバー連携（Firebase Realtime Database）

旧 iPhone アプリと同じデータベース（`taxi-location-sharing`）を、同じ形式で使います。

- 位置の共有：メニューの「車両コード設定」でコードを登録すると、`taxi_locations/<車両コード>` に位置と空車／実車を送ります。「位置を非公開」をオンにすると送信を止め、登録を消します。
- 近隣車両：10 分以内に位置を更新した車両を地図に表示します（緑＝空車、オレンジ＝実車）。
- お客様用 QR コード：`view.html?c=<車両コード>` を開く QR を表示します。お客様側は API キー不要です。
- 探索ナビ：`explore_nav_data/demand_grid` の GPS 需要データと、端末内の配車記録を合わせて経由地を選びます。
- SOS 通知：S の発動中は `sos_alerts/<車両コード>` に位置を書き、ほかの車両の地図に表示します。

## 制約

- 位置の記録と共有、ナビ、S の録画は、画面を表示している間だけ動きます。
- 配車記録・乗車記録・SOS 録画は端末のブラウザ内に保存されます（端末間では共有されません）。
- データベースのルールが「誰でも読み書き可」のままです。ログインを入れてルールを絞る対応が残っています。

## ファイル

- `index.html` / `css/app.css`：画面
- `js/app.js`：地図と各機能
- `js/logic.js`：計算ロジック（距離、曲がり角の検出、需要エリアなど）
- `js/ic.js`：高速 IC の区間データ
- `js/cloud.js`：サーバーとの通信
- `view.html`：お客様用ページ（タクシーの現在地）
- `vendor/`：同梱ライブラリ（QR コード生成、Leaflet）

## テスト

- `node tests/logic.test.mjs`：計算ロジックの単体テスト
- `python3 tests/smoke.py`：地図を模擬してブラウザで主要な操作を通すテスト（Playwright と Chrome が必要）

## 設定リンク

`?key=<APIキー>&code=<車両コード>&plate=<ナンバー>` を付けた URL を開くと、その内容が端末に保存されます（保存後は URL から消えます）。利用者に手入力させずに渡すためのものです。
